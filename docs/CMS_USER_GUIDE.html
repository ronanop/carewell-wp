1. How the system works

Care Well’s public website is not edited in WordPress anymore. Content lives in Sanity CMS. The Next.js website reads that content and displays it.

End-to-end flow

You edit in Studiocarewellcms.sanity.studio
→
Publishsaves to Sanity cloud
→
Website reads CMSNext.js on Hostinger
→
Visitors see pagescarewellmedicalcentre.com

Leads (contact forms) go to a separate admin at /admin on the website — not inside Sanity.

Two “admins” — don’t mix them up
  • Sanity Studio = content (services, blogs, images, SEO).
  • Website /admin = leads inbox, staff users, Services mega-menu links.

Hero tab — what visitors see first

  1. Tagline — optional subtitle under the H1. Leave blank to hide.
  2. Desktop hero image — wide image for large screens.
  3. Mobile hero image — taller crop for phones (optional; falls back to desktop).
  4. Alt text — required on each image for SEO/accessibility (expand the image field).
  5. Primary / Secondary CTA labels — button text (e.g. Book Free Consultation / WhatsApp).
  6. Quick facts — short label/value pairs under the hero.
If you still see a single field named “Hero image” Schema was updated to “Desktop hero image” + “Mobile hero image”. Hard-refresh Studio (Ctrl+Shift+R) or sign out/in. Confirm schema deploy already ran (npm run sanity:deploy-schema).

Other important groups (fill as needed)

  • Overview / How it works / Before & after / Candidacy — medical content sections.
  • Pricing / Booking / Doctor / FAQs / Related — conversion & trust.
  • Page builder (if enabled) — section order for the main column.
  • Empty sections usually hide automatically on the website — leave unused fields blank.

Upload workflow
  1. Click Upload (or drag into the dashed box).
  2. Wait until the thumbnail appears.
  3. Open the image field → set Alt text (describe the photo, not “image1”).
  4. Adjust Hotspot if available so the face stays centered when cropped.
  5. Publish the document.

6. Creating a new service

Services → +
→

→

→
Set URI Path
→
Hero + content
→
Publish
  1. Left sidebar → Services → create new.
  2. Enter Page title (this becomes the H1).
  3. Click Generate on Slug.
  4. Set URI Path carefully — this is the public address. Example: /laser-hair-removal-in-delhi/
  5. Fill Hero (images + CTAs), then other sections you need.
  6. Add SEO title/description.
  7. Publish.
  8. Open the live URI on the website. If you changed an old URL, add a Redirect.
URI mistakes break Google rankings Prefer keeping the same URI as the old WordPress page. If you must change it, create a Redirect (old path → new path) before or right after publish.

7. Blog posts

  1. Sidebar → Blog posts → create or open.
  2. Set Title, generate Slug, set URI if used.
  3. Add excerpt, main image (+ alt), categories/tags as available.
  4. Write the Body with headings (H2/H3), lists, images, embeds.
  5. Fill SEO.
  6. Publish → check under /blogs/ and the post URL.
Body tips Use real headings for structure (helps SEO). Compress large photos before upload. Don’t paste huge Word tables as screenshots when a simple list will do.

8. Generic pages

Pages in Studio are generic documents. Many marketing pages (Home, About, Contact, Privacy) are handcrafted in the website code and may not be fully driven by these Page documents. Prefer editing Services and Blog posts for day-to-day content.

Ask the development team before creating a new top-level marketing page in Studio if you expect a brand-new public route.

10. Publishing, drafts & preview

  • Draft = saved but not live.
  • Publish = live for the website (after cache refresh — see §13).
  • Unpublish removes from the public API — use carefully on important URLs.
  • Use Review changes before publishing large edits.
Preview If Presentation / preview is configured, you can open a draft preview of the website. Preview requires a valid signed link — random “draft mode” URLs without a secret will fail (by design).

11. Redirects (old URL → new URL)

  1. Sidebar → Redirects → create.
  2. From: old path, e.g. /old-page/
  3. To: new path or full URL, e.g. /new-page/
  4. Mark as permanent (301) when the move is final.
  5. Publish.

Redirects are applied by the website middleware. Test in a private browser window.

14. Troubleshooting

ProblemLikely causeWhat to do
Can’t sign in to Studio Not invited / wrong account Ask Admin to invite your email in Sanity Manage
New fields missing (e.g. Mobile hero) Browser cache / old Studio bundle Hard refresh; confirm schema deploy; sign out/in
Published but site unchanged ISR cache / wrong URI Wait / hard refresh; verify URI Path; check draft vs published
Image won’t upload Huge file / network / permissions Compress under ~2–5 MB; retry; check Editor role
Can’t publish — validation error Missing required field (often Alt text) Read the red error; fill Alt text / required fields
404 on service URL URI mismatch or unpublished Match URI to address bar; publish; add Redirect if moved
Mobile shows wrong crop No mobile image / hotspot Upload Mobile hero image at 1080×1350; set hotspot
Form leads not in Sanity Expected — leads aren’t CMS content Check website /admin/leads and email/SMTP
Mega menu wrong links Not edited in Studio Navigation alone Edit /admin/menu → Save menu
Preview / draft link fails Missing preview secret Open preview from Studio Presentation only

15. Quick checklists

Before publishing a service

  • Page title is correct H1
  • URI Path matches final URL
  • Desktop hero uploaded (1920×900)
  • Mobile hero uploaded (1080×1350) if needed
  • Alt text on images
  • SEO title + description
  • FAQs / CTAs reviewed
  • Publish clicked
  • Live URL checked (Incognito)

Before publishing a blog post

  • Title & slug set
  • Featured image + alt
  • Excerpt filled
  • Body headings structured
  • SEO fields filled
  • Publish + check /blogs/
Need help? Content questions → clinic editor lead.
Access / Studio invite → Sanity project Administrator.
Website bugs / deploy / leads email → development team (Hostinger + Neon + SMTP).
